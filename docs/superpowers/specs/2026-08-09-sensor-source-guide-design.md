# Sensor 框架源码说明文档设计

## 目标

生成一份面向维护者和 MCU 移植人员的中文源码导读，逐文件解释当前生产代码的职责、结构体设计、函数语义和层间调用关系。文档只描述仓库中的实际实现，不重复尚未实现的设计草案。

## 范围

- 覆盖 `src/` 下全部 `.c`、`.h` 文件。
- 覆盖 `examples/host_demo/main.c`，用于说明四层模块如何完成装配和端到端运行。
- 不逐文件讲解 `tests/`、CMake、Python 检查工具或构建脚本。
- 不修改任何生产源码、接口或运行行为。

## 组织方式

最终文档保存为 `doc/sensor_framework_source_guide_20260809.md`，按以下顺序组织：

1. 阅读导航和四层依赖规则。
2. 关键数据流与调用关系 Mermaid 图。
3. 工具层 `src/tool`。
4. 接口层契约 `src/iface`。
5. 接口层 Host、模板 Port `src/ports`。
6. 协议层 `src/proto`。
7. 功能层基础、滤波器和应用模块 `src/func`。
8. `examples/host_demo/main.c` 的装配与演示流程。
9. 关键结构体关系、扩展入口和阅读建议。

每个文件固定说明：

- 文件职责和所属层级；
- 公开结构体、枚举和关键字段的设计理由；
- 公开函数的参数、返回值、状态变化和调用约束；
- `.c` 中重要内部函数的作用；
- 该文件允许依赖和禁止依赖的层级。

纯配置头、仅声明的 HAL 头和模板占位文件也必须列出，明确说明“为什么没有运行逻辑”，不能因代码量少而遗漏。

## 事实核对方法

- 函数和结构体名称以当前 `main` 工作区实际源码为准。
- 函数语义同时核对头文件契约和 `.c` 实现，避免只根据名称推测。
- 标明静态内存所有权、队列满策略、定点单位、错误码和 MQTT 状态机等容易误用的约束。
- 文档完成后，将列出的源码文件与 `rg --files src examples/host_demo` 对照，确保无遗漏或虚构文件。
- 扫描文档中的函数名并与源码符号交叉检查；对内部辅助函数使用“内部函数”标识，避免误当公共 API。

## 表达原则

- 使用中文解释，保留原始 C 标识符。
- 先说用途，再说实现细节；避免逐行翻译代码。
- 对短小的声明文件采用表格，对复杂模块（Sensor 核心、温度驱动、MQTT、runtime、demo）采用分节说明。
- 明确区分“当前实现”“设计意图”和“后续扩展建议”，不把建议描述成现有能力。
