# 下一版本更新建议

以下项目建议在 v0.2 按优先级实施。

## 1. STM32F4 实际 Port 与硬件在环 CI

动机：模板和 host_sim 只能验证接口边界，不能发现真实 I2C 时序、中断或缓存问题。

约束：厂商 HAL 类型仍不得暴露到接口层以上。

验收：至少一块 STM32F4 开发板连续采样 TMP75 24 小时；覆盖总线 NACK、超时恢复和 tick 回绕；CI 保存串口测试报告。

兼容性：不修改现有上层 API，只新增 Port 和板级装配。

## 2. TLS 传输与 MQTT QoS 1

动机：生产 MQTT 通常需要加密和至少一次交付。

约束：TLS 放在 hal_net 安全传输实现；MQTT 核心不依赖具体 TLS 库。

验收：证书校验、连接失败、PUBACK、重发、重复包和离线队列测试通过。

兼容性：扩展 MQTT 配置和状态，不改变 QoS 0 调用方默认行为。

## 3. RTOS 消息适配器

动机：允许业务任务安全地向唯一 Sensor owner 发送命令。

约束：Sensor 核心继续保持单 owner，功能层仍不得直接依赖 RTOS 或 plat_os。

验收：提供协议层或装配层消息适配器，在双任务压力测试下无数据竞争和死锁。

兼容性：裸机协作式模式保持默认。

## 4. SHT3x 与 NTC 温度 Profile

动机：验证数字 CRC 器件和 ADC 模拟 Sensor 都能复用同一功能框架。

约束：SHT3x CRC 和 NTC 换算位于协议层，功能层只使用标准温度设备。

验收：SHT3x CRC 错误向上传播；NTC 覆盖 ADC 边界、开路、短路和查表插值。

兼容性：只新增协议设备实例。

## 5. 更多定点滤波器

动机：覆盖低噪声、缓慢变化和模型估计场景。

约束：继续使用直接 ops、调用方状态和 int32_t 公共工程量。

验收：新增一阶低通和定点卡尔曼；与离线参考向量比较；验证溢出和重置。

兼容性：滤波核心无需修改。

## 6. 资源报告与更强测试

动机：不同 MCU 需要可预测的 Flash、RAM 和栈预算。

约束：报告工具不进入固件运行时。

验收：构建输出每层代码大小、静态 RAM、队列与滤波状态预算；CI 增加覆盖率、模糊测试和变异测试。

兼容性：只增加构建与质量工具。
